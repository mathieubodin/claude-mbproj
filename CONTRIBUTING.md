# Contributing to claude-mbproj

This document covers how to work on the plugin itself. For what the plugin *is* and how to
install it as a user, see [`README.md`](README.md).

## Prerequisites

Install the tooling listed in [`SETUP_ENV.md`](SETUP_ENV.md), then verify it:

```bash
make check-dev-env
```

The scaffolding engine is written in Python and needs **Python 3.11+** (it uses the standard
library `tomllib`). See [`SETUP_ENV.md`](SETUP_ENV.md) for the install commands.

## Repository layout

```text
.claude-plugin/          plugin.json + marketplace.json (distribution manifests)
skills/mbproj-scaffold/
  SKILL.md               skill entry — orchestration (asks, applies, installs)
  scripts/               the deterministic engine (Python)
  templates/             the generic files the engine ships into target repos
docs/spine.md            authoritative design invariants (read this first)
```

Everything else at the root (`Makefile`, `mbproj.mk`, `prek.toml`, `cliff.toml`,
`.claude/rules/`, …) is **generated by the plugin on itself** — this repo is scaffolded by
its own skill. Do not hand-edit a generated file: change the template or the engine, then
re-apply (see below).

## How the engine works

Read [`docs/spine.md`](docs/spine.md) for the invariants. In short:

- `mbproj_manifest.py` — reads and writes `.config/mbproj.toml`, the source of truth for
  applied layers and parameters.
- `mbproj_writer.py` — writes an *owned* file: do-not-edit banner plus content, rewritten in
  full on every run.
- `mbproj_shared.py` — the two mechanisms for files the project also owns: an anchor line
  (`include mbproj.mk`, `@import`) or a delimited `mbproj:managed` block regenerated in full.
- `mbproj_layers.py` — the per-layer registry: owned files, Make targets, tool checks,
  shared-file contributions, lint excludes.
- `mbproj_apply.py` — composes all of the above from the manifest and writes it out.

Mechanical file output lives in Python, not in `SKILL.md` prose, because re-runs must be
**byte-identical** — a guarantee a language model cannot provide.

## Testing a change

Two things must hold for any change: the output is correct, and a second run changes nothing.

Apply to a throwaway repo and check idempotency:

```bash
T=$(mktemp -d) && git -C "$T" init -q
python3 skills/mbproj-scaffold/scripts/mbproj_apply.py "$T" \
  --layer lint_format --layer guards --project-name demo
make -C "$T" lint

# a second run must produce no change
find "$T" -path "$T/.git" -prune -o -type f -print | sort | xargs sha256sum > /tmp/a
python3 skills/mbproj-scaffold/scripts/mbproj_apply.py "$T" \
  --layer lint_format --layer guards --project-name demo
find "$T" -path "$T/.git" -prune -o -type f -print | sort | xargs sha256sum > /tmp/b
diff /tmp/a /tmp/b && echo "idempotent"
```

Then dogfood on this repository — it is the first non-regression test:

```bash
python3 skills/mbproj-scaffold/scripts/mbproj_apply.py . --layer lint_format
git diff          # expected: empty, unless your change was meant to alter the output
make lint
```

When touching a shared-file mechanism, also verify against a repo that already has content in
`Makefile`, `CLAUDE.md`, `.gitignore`, or `SETUP_ENV.md`: project-authored content must survive
untouched, and obsolete mbproj lines must disappear rather than accumulate.

## Adding or changing a layer

1. Put generic file content in `skills/mbproj-scaffold/templates/`, never inline in Python.
2. Register it in `mbproj_layers.py`: owned files, `mk` block, `main_targets`, `check_targets`,
   `claude_imports`, `setup_env_sections`, `gitignore_lines`, `exclude_dirs`.
3. Declare dependencies in `DEPENDS_ON` — they are enforced at apply time.
4. Add the tool's install section as `templates/setup_env/<tool>.md`; `check-dev-env` and
   `SETUP_ENV.md` compose themselves from the applied layers.
5. Keep excludes narrow: exclude `.claude/skills/bmad-*`, not all of `.claude/skills`, so a
   project's own files stay linted.
6. Test as above, then dogfood.

## Commits and hooks

Commits follow [Conventional Commits](https://www.conventionalcommits.org). Install the hooks
once per clone:

```bash
make install-hooks
```

The `pre-commit` hook runs `make lint`; the `commit-msg` hook runs commitlint. `CHANGELOG.md`
is generated — never hand-edit it; run `make changelog` instead.

## Releasing

Bump the version in **both** `.claude-plugin/plugin.json` and
`.claude-plugin/marketplace.json` (they must agree), regenerate the changelog, then validate
the manifests:

```bash
claude plugin validate .
```
